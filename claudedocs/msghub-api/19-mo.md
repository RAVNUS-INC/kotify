# 5.2 MO 수신
> 원문: https://doc.msghub.uplus.co.kr/rest-api/05부가서비스/0502mo/ · 확인일 2026-10-16

## 한눈에 보기

고객이 보낸 MO(Mobile Originated) 메시지를 받는 방법은 두 가지다. 웹훅 전달(가입 때 등록한 URL 로 push)과 조회 API(`GET /mo/v1/msg`) 다. 원문은 "폴링"이라는 말을 쓰지 않지만 조회 API 가 그 역할이다.

| 기능 | Method | 경로 | 호스트 |
|---|---|---|---|
| MO 메시지 조회 | GET | `/mo/v1/msg` | api |
| MO 메시지 전달 (웹훅) | POST | `{WEBHOOK_URL}` (고객 서버) | 고객 서버 |
| MMS MO 컨텐츠 조회 | GET | `/mo/v1/file/{moKey}` | api |
| MO 컨텐츠 생성 샘플 | GET | `/mo/direct/v1/mmsMoSample` | api |

## 공통 개념

### 수신 방식

| 방식 | 설명 |
|---|---|
| 웹훅 | MO 가입 시 받은(등록한) 웹훅 URL 로 msghub 가 POST. 성공 시 큐에서 삭제, 실패 시 재처리 가능 |
| 조회 | `GET /mo/v1/msg` 로 보관 중인 MO 를 직접 조회 |

### moType 코드

| 값 | 의미 |
|---|---|
| SMSMO | 일반 SMS |
| MMSMO | MMS |
| RCSMO | RCS |

### MO 항목 필드 (조회 응답 `data[]` 와 웹훅 `moLst[]` 가 같은 구조)

| 필드 | 타입 | 설명 |
|---|---|---|
| moKey | String | MO 메시지 고유 키 |
| moNumber | String | 수신번호 (고객이 문자를 보낸 대상 번호, 예시 `15440000`) |
| moType | String | 메시지 유형 (SMSMO / MMSMO / RCSMO) |
| moCallback | String | 발신번호 (고객 단말 번호) |
| productCode | String | 상품 코드 |
| moTitle | String | 메시지 제목 (MMS/RCS) |
| moMsg | String | 메시지 내용 |
| telco | String | 이통사 (예시 `LGU`) |
| contentCnt | Integer | 컨텐츠 개수 |
| contentInfoLst[].contentName | String | 컨텐츠 파일명 |
| contentInfoLst[].contentSize | String | 컨텐츠 크기 |
| contentInfoLst[].contentExt | String | 컨텐츠 확장자 |
| contentInfoLst[].contentUrl | String | 컨텐츠 URL |
| moRecvDt | String | 수신 일시 |

### 시각 필드 형식 (moRecvDt)

- 원문은 "수신 일시"라고만 적고 형식을 정의하지 않는다. 조회·웹훅 예시 모두 `2024-01-29T09:22:55` 모양(ISO 8601 에서 시간대 표기 없음, 초 단위, 소수점 없음)이다.
- 시간대 표기(`Z`, `+09:00`)가 없다. 이 프로젝트의 별도 기록(2026-04 운영 캡처)에서는 naive KST 로 확인되었으나, 이 문서 원문에는 근거가 없다.

> 원문 확인 필요: `moRecvDt` 의 시간대(KST 로 추정)와 형식 보장 여부. 값이 비어 올 수 있는지도 원문에 없다. 파서는 시간대 없는 값과 빈 값을 모두 방어할 것.

## MO 메시지 조회

`GET /mo/v1/msg`

보관 중인 MO 메시지를 조회한다. 쿼리 파라미터는 원문에 정의되어 있지 않다(예시도 파라미터 없음).

| 구분 | 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| Header | Authorization | String | ● | 사용자 인증 토큰 |
| Header | Content-Type | String | ● | `application/json` |

응답 `data[]`: 위 "MO 항목 필드" 와 동일.

응답 예시

```json
{
  "code": "10000", "message": "성공",
  "data": [
    { "moKey": "1234", "moNumber": "15440000", "moType": "SMSMO", "moCallback": "01000000000",
      "productCode": "", "moTitle": "테스트", "moMsg": "테스트", "telco": "LGU",
      "contentCnt": 1,
      "contentInfoLst": [ { "contentName": "", "contentSize": "", "contentExt": "", "contentUrl": "" } ],
      "moRecvDt": "2024-01-29T09:22:55" }
  ]
}
```

> 주의
> - MO 는 최대 7일간 보관되고 이후 자동 삭제된다.
> - MMS 는 `contentInfoLst` 에 컨텐츠 정보만 있고, 실제 컨텐츠는 "MMS MO 컨텐츠 조회" API 로 받아야 한다.
> - 원문 확인 필요: 조회한 MO 가 큐에서 빠지는지(이미 읽은 건 다시 오는지), 페이징·건수 상한·조회 기간 파라미터 유무는 원문에 없다.

## MO 메시지 전달 (웹훅)

`POST {WEBHOOK_URL}`

msghub 가 고객이 등록한 웹훅 URL 로 MO 를 보낸다. 고객 서버가 받는 쪽이다.

수신 Header

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| Content-Type | String | ● | `application/json` |

수신 Body

| 필드 | 타입 | 설명 |
|---|---|---|
| moCnt | Integer | MO 건수 |
| moLst[] | Array | MO 항목 (필드는 위 "MO 항목 필드" 와 동일) |

고객 서버가 돌려줄 응답 (표 머리는 원문에 "Requset Body" 로 중복 표기)

| 필드 | 타입 | 설명 |
|---|---|---|
| code | Integer | 결과 코드 |
| message | String | 결과 메시지 |

수신 예시

```json
{
  "moCnt": 1,
  "moLst": [
    { "moKey": "1234", "moNumber": "15440000", "moType": "SMSMO", "moCallback": "01000000000",
      "productCode": "", "moTitle": "테스트", "moMsg": "테스트", "telco": "LGU",
      "moRecvDt": "2024-01-29T09:22:55", "contentCnt": 1,
      "contentInfoLst": [ { "contentName": "", "contentSize": "", "contentExt": "", "contentUrl": "" } ] }
  ]
}
```

성공 응답 예시

```json
{ "code": "10000", "message": "success" }
```

> 주의
> - 웹훅 URL 은 사전에 등록해야 한다. 공개(public) 웹훅 URL 만 지원하며 전용선 연결에서는 지원하지 않는다.
> - 수신 성공: code `10000`, message `success`. 실패: code 를 `20000` 이상으로, 실패 메시지와 함께 돌려준다.
> - 성공하면 msghub 큐에서 삭제되고, 실패하면 재처리할 수 있다.
> - 한 번에 여러 건(`moLst`)이 올 수 있다. 건별 처리는 `moKey` 기준으로 하는 편이 안전하다(중복 수신 대비).
> - 원문 확인 필요: 재전달 횟수·간격·중단 조건, 중복 전달 가능성, 응답의 HTTP 상태 코드 처리, 응답 `code` 타입(표는 Integer 인데 예시는 문자열 `"10000"`)은 원문에 없다. 위 마지막 bullet 의 `moKey` 중복 대비는 이 문서 작성자의 권고이며 원문 내용이 아니다.
> - 원문 예시 JSON 은 `moRecvDt` 뒤 쉼표가 빠져 있다(오타). 실제 payload 는 정상 JSON 일 것으로 본다.

## MMS MO 컨텐츠 조회

`GET /mo/v1/file/{moKey}`

MMS MO 에 첨부된 파일(이미지·동영상 등)을 받는다. 응답은 JSON 이 아니라 파일 본문이며 Content-Type 은 파일 형식에 따라 달라진다.

| 구분 | 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| Path | moKey | String | ● | MO 메시지 고유 키 |
| Header | Authorization | String | ● | 사용자 인증 토큰 |
| Header | Content-Type | String | ● | `application/json` |

요청 예시

```
GET https://api.msghub.uplus.co.kr/mo/v1/file/1234
Authorization: Bearer {token}
```

> 주의
> - 컨텐츠도 최대 7일 보관 후 삭제된다.
> - 컨텐츠 URL 은 일회성이며 24시간 이내에만 유효하다.
> - 용량이 크면 다운로드에 시간이 걸린다.
> - 원문 확인 필요: 한 MO 에 컨텐츠가 여러 개일 때 파일을 어떻게 구분해 받는지(경로에 `moKey` 만 있음)는 원문에 없다.

## MO 컨텐츠 생성 샘플

`GET /mo/direct/v1/mmsMoSample`

MO 컨텐츠 생성 샘플 데이터를 돌려주는 개발·테스트용 API.

| 구분 | 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| Header | Authorization | String | ● | 사용자 인증 토큰 |
| Header | Content-Type | String | ● | `application/json` |

응답: `data`(Object) 에 샘플 데이터. 구체 필드는 원문에 없다.

> 주의
> - 실제 MO 와 무관한 샘플이며 운영 환경에서는 쓰지 않는다.
> - 원문 확인 필요: 응답 `data` 의 구조.
